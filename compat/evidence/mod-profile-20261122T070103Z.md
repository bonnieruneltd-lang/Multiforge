# Mod profile evidence 2026-11-22

Environment: Forge 47.4.29, Java 17.0.21 (Temurin), MultiForge `1.0.0-alpha.1`, a master
process and one ForgeGradle dev server (`run/`), fresh flat world. Mods were taken from the
pinned manifest (`compat/required-mods.json`).

## Ksyxis 1.4.6 + `/forceload` — the old finding does not reproduce

```
[RCON live1] forceload add 0 0
Marked chunk [0, 0] in minecraft:overworld to be force loaded

[RCON live1] forceload query
A force loaded chunk was found in minecraft:overworld at: [0, 0]

# 3 seconds later
[RCON live1] forceload query
A force loaded chunk was found in minecraft:overworld at: [0, 0]

[RCON live1] multiforge chunk 0 0
Chunk world,0,0 owner=unowned local=false loaded=true subscribers=[]

[log] Ksyxis: Ready to remove unneeded chunks. (platform: forge, version: 1.4.6, mixin: 0.8.5)
[log] Ksyxis: Speeding up the world loading... Delete the mod, if it got stuck after this message.
```

**Result:** the ticket survived and the chunk stayed loaded. KNOWN_ISSUES 15 (tickets
disappearing, observed with Ksyxis 1.4.6 in session 3) did not reproduce on this
Forge 47.4.29 build. The cluster harness no longer has to remove Ksyxis to find a common
chunk; the earlier workaround is kept only as a fallback.

## Radium 0.12.4 + ServerCore 1.5.2 — dev-run limitation, production profile

A ForgeGradle dev server refuses to start with Radium installed:

```
Mixin apply failed lithium.mixins.json:math.sine_lut.MixinMathHelper -> net.minecraft.util.Mth:
InvalidMixinException Overwrite target "m_14031_" was not located in target class
net/minecraft/util/Mth
```

This is the usual production-mod refmap limitation of a dev run (SRG names vs the official
mappings used by `runServer`), not a MultiForge regression. The pinned **production**
installation remains the way to test them: session 3 recorded
`ServerChunkCacheMixin->@Redirect::servercore$noList` being skipped because Radium's lithium
redirect has priority 1000, with the server still correct and at 20 TPS
(`docs/REQUIRED_MOD_COMPATIBILITY.md` rows 12-13). The supported choices are documented in
`docs/COMPATIBILITY_PROFILES.md`.

## BetterAutoSave 0.20.2 — same dev-run limitation

```
shinoyuki_betterautosave.mixins.json:MinecraftServerMixin FAILED during APPLY:
@Shadow method m_129903_ was not located in the target class net.minecraft.server.MinecraftServer
```

The production installation used in session 3 ran the autosave pipeline, `save-all flush` and
a graceful shutdown; the only output was the cosmetic `level.dat ... MISSING` probe before
MultiForge downloaded it (KNOWN_ISSUES 17). Use a production install for this mod.

## Decision

Ksyxis stays supported as installed. Radium and ServerCore are supported individually; when
both are present the documented consequence is that one ServerCore chunk-cache optimization is
inactive. No config can raise the skipped mixin's priority, so the profile is a deployment
choice, not a flag. See `docs/COMPATIBILITY_PROFILES.md`.

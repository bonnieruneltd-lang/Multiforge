# Production gameplay mod checks 2026-11-22

Production Forge 47.4.29 server (not a dev run) with MultiForge, Combatlog 2.8.5, Just Player
Heads 4.5 + Collective 8.87 and Beautified Chat Server 4.0. Two production servers
`live1`/`live2` (RCON 25575/25576) and one master; headless players BotA/BotC/BotD/BotE/BotF
on live1 and BotB on live2.

## Combatlog 2.8.5 — FUNCTIONAL

BotF was set to survival and damaged by BotA:

```
[RCON] damage BotF 1 minecraft:player_attack by BotA
[BotF] SYSTEM {"color":"red","text":"You are in combat do not leave! 28 seconds left"}
```

BotF then disconnected through the bot control socket; the server applied the configured
punishment:

```
[...] BotF lost connection: Disconnected
[...] BotF has died of cowardice
```

That is Combatlog's `disconnect_death` behavior for leaving combat, so the main function is
verified on the correct server. No item drop was created (the test player had an empty
inventory).

## Just Player Heads 4.5 — no head on a player kill

`config/serilum/justplayerheads.json` has `playerDropsHeadOnDeath=true` and
`playerHeadDropChance=1.0`. BotD and BotE were set to survival and killed by BotA:

```
[...] BotD was slain by BotA
[...] BotE was slain by BotA
```

`execute if entity @e[type=item,distance=..100]` returned nothing and there was no
`player_head` item in the world. `keepInventory=false`, `doMobLoot=true`. The mod reports as
loaded in `/multiforge compat`, but its death drop did not occur in this environment. The row
stays LOADING with this negative evidence; the cause (event ordering with Combatlog/Collective,
offline skin, or a version issue) needs a focused test.

## Beautified Chat Server 4.0 — local only in this run

BotA (live1) sent `hello-beautified`. live1 logged the vanilla line
`[Not Secure] <BotA> hello-beautified`; live2 logged plain `hello-beautified`; BotB received
`{"text":"hello-beautified"}` with no timestamp or colours. The mod is enabled with the default
`%timestamp% | %username%: %chatmessage%` format, so its formatting was not applied to the
forwarded chat in this run. The row stays PARTIAL; cross-server formatting is a real gap, not
just an untested edge.

## Reproduction notes

The production install is required for these mods: Combatlog and Collective fail a ForgeGradle
dev run with SRG `@Shadow` errors. The test used the official Forge 47.4.29 installer, two
copies of its `libraries` (hardlinked), the MultiForge jar and the four mod jars in `mods/`.

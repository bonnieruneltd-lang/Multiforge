# Player-driven required-mod evidence 20261122T043800Z

Dedicated Forge 47.4.29 servers `live1`/`live2` (not Gradle dev runs), 21 jars in `mods/`
(MultiForge + 19 server mods + 2 libraries, Ksyxis excluded per the harness note) and the
`UltimateAntiSeedCracker.zip` data pack. `18/19` required targets loaded on each server.
The two-server harness passed **18/18** in `compat/evidence/cluster-20261122T043401Z.md`.

Two headless bots with `minecraft-protocol` 1.68.0 (`GameplayBot`, `TPABot`) ran on `live1`
at `(90.5, 80, 72.5)` near a purpose-built oak tree.

## 1. Timber Strike 1.3 — FUNCTIONAL

Setup: stone platform at y=79, four `oak_log` at `(92, 80..83, 72)`, three `oak_leaves`
around the top. The bot held an iron axe in survival mode and sent one start/stop dig at the
base log.

Result: the base log disappeared, then the remaining three logs and the leaves were air
within the same three-second window. The probe reset a marker block before each conditional
`setblock` and reported `air` for y=80, 81, 82, 83 and 84; the axe's `Damage` was 13, so the
tree functions had consumed durability for the extra logs. This is the real 1.3 data-pack
path (the 3.0 artifact ships 1.20.2 syntax and is not used).

## 2. Fast Leaf Decay 2.0.0 — FUNCTIONAL

The same tree had `oak_leaves` at `(91,83,72)`, `(93,83,72)` and `(92,84,72)`. After the trunk
was removed by the Timber break, all three leaf positions were `air` within the same
three-second probe. Vanilla decay alone would take much longer, so the mod's accelerated
scheduled ticks are active.

## 3. TPA Teleport 1.0.0 — PARTIAL (same-server path verified)

`TPABot` sent `/tpa GameplayBot`; the server delivered:

```
TPABot:      Teleport request sent to GameplayBot.
GameplayBot: TPABot wants to teleport to you. Use /tpaccept TPABot or /tpadeny.
```

`GameplayBot` then sent `/tpaccept TPABot` (the argument is required); both players ended at
`[90.5d, 80.0d, 72.5d]` and TPABot received `Teleported to GameplayBot.` The cross-server
hand-off still relies on MultiForge's normal player transfer and was not exercised in this
run, so the row stays PARTIAL rather than claiming the full target behaviour.

## 4. Beautified Chat [Server] 4.0 — PARTIAL

`TPABot` sent `hello-cluster-test`; the clientbound `player_chat` packet contained the
formatted component `04:36 | TPABot: hello-cluster-test` with the mod's timestamp and colour
fields. Plain vanilla would be `<TPABot> hello-cluster-test`. Formatting therefore works;
cross-server chat formatting was not separately asserted, so the row is PARTIAL.

## 5. Get It Together, Drops! 1.3 — FUNCTIONAL (natural drop path)

Two `stone` blocks were placed two blocks apart on the test platform and broken by the
survival player with a diamond pickaxe. The two cobblestone drops merged into one item entity:

```
execute as @e[type=item] run data get entity @s Item
Cobblestone ... {id: "minecraft:cobblestone", Count: 2b}
```

The server config had `radius = 2.0` and `checkY = true`
(`world/serverconfig/getittogetherdrops-server.toml`). The earlier summoned-item test was
inconclusive because the summon path bypassed the mixin; this natural block-drop test is the
one used for the FUNCTIONAL rating.

## 6. Just Player Heads / Combatlog / Minecarts

`/kill TPABot` and a PvP death still produced **no `player_head` item**. The mod's head cache
builds a textured head from the victim profile; offline bots have no skin properties, so the
drop path cannot be exercised with this harness. The `/jph head Notch 1` command was not
registered on the dedicated server (Brigadier: unknown command), so the mod's command path is
also unverified there. Both rows stay LOADING. Combatlog did not show its action-bar tag in
the short PvP window, and minecart speed/chunk-loading was not exercised; those stay LOADING.
